# Vatesteed 🐎

競馬ファンが数字の背後を読んでいる思考を、対話しながら AI に学習させていくエージェントです。

> 🚧 **β版です。** 開発中のため、機能も構成も予告なく変わります。

## Vatesteed のコンセプト

### 名前の由来

vates（ラテン語で「預言者」）と steed（駿馬）を組み合わせた名前です。**優駿を預言する者**、という意味を込めています。

### このアプリでやりたいこと

競馬のデータは、着順、タイム、人気といった「結果」として記録されます。ただそれは起きたことの記録であって、その馬がどれだけ強いか、どんな状態だったかを直接表しているわけではありません。

競馬ファンは、そこを補正しながら見ています。数字の背後にある経緯や事情を読み取って、この着順は信用していい、これは度外視していい、と評価を上下させている。この読み取りは、データにした時点でこぼれ落ちます。

一方で、全馬の戦績を何年分も追いかけて突き合わせる作業は、人間には量が多すぎます。

**この読み取りを、AI ができるようにするのが Vatesteed の目的です。** 覚えさせたいのは「この馬は買い」という結論ではなく、そう考えるまでの筋道の方です。結論だけを覚えた形は、条件が変わった瞬間に効かなくなります。

そこで、いまは役割を分けています。

- **AI** が、膨大なデータを集めて解析する
- **人間** が、データに表れない文脈を読んで解釈を加える

### 目指している形

**この分け方は固定ではありません。** 最終的に目指しているのは、人間が渡している解釈を AI 側が学習して引き受け、**完全に自動で動く形**です。

そこへ一足飛びには行きません。はじめのうちは精度を上げるために、人間が意識して知見を渡します。その先で目指しているのは、**人間が普通に競馬の話をしているだけで、その裏で AI が学習して精度が上がっていく形**です。学習のための作業を人間に発生させないことを、完成形の条件だと考えています。

**この過程を一緒に作っていくこと自体を、プロジェクトの中身に据えています。**

### どう実現するか

**自分で調べる。** 枠順や各馬の情報は Vatesteed が自分で集めてきます。取得できないものや判断に迷うものを勝手に埋めることはせず、人間に確認します。

**分析して、予想する。** 集めた情報から各馬を評価し、レースの展開を読み、着順を予想します。結論だけでなく、**なぜそう判断したのか**まで一緒に出します。

**解釈を受け取って、覚える。** 人間から渡された文脈や解釈を蓄積します。ここで溜まるのは単なるデータではありません。**人間の解釈を含んだ、Vatesteed にしか無い情報**が積み上がっていきます。

**振り返って、更新する。** レースが終わったら、展開や着順の予想がどこまで合っていたかを検証します。そこで各馬、騎手、厩舎、コースなどへの評価を更新し、次に備えます。

この往復を重ねるほど内側の蓄積が厚くなり、外から取ってくる必要は減っていきます。予想は note の記事と、このリポジトリで作っているダッシュボードで公開します。

### 今後の展望

Vatesteed は**レース予想アプリではありません。** 使い道はこれからも増やしていきます。

いま考えているのは、たとえばこんなことです。

- 過去のレースを使ってシミュレーションする
- 先のビッグレースに向けて、出走が見込まれる馬の展望を分析する
- 解釈を加える部分を、少しずつ AI 側に寄せていく。蓄積が厚くなるほど AI にできることも増えるはずです
- ダッシュボードやスマートフォンからも操作できるようにする

ここに並べたものは思いついている一例で、これで固定するつもりはありません。

## Vatesteed の技術基盤

> ⚠️ ここから先は開発中の内容を多く含みます。構成は今後変わります。

### 全体の構成

エージェントフレームワークの **eve** の構成でプロジェクトを作り、**Next.js** を同居させてダッシュボードを同じリポジトリに置いています。

ツールのロジックはすべて `lib/` に集約し、エージェント側とダッシュボード側の両方から同じものを呼びます。`agent/tools/` は `lib/` を呼ぶだけの薄いラッパーです。エージェントの手順は `agent/skills/` にスキルとして置き、eve の `SKILL.md` の規約に従います。

現時点では eve のランタイムは使用しておらず、**Claude Code がエンジンとして `lib/` を直接呼ぶ形**で動かしています。エージェントへの指示は `AGENTS.md` に集約し、`CLAUDE.md` はそこへの入口として置いています。

蓄積したナレッジは **Neon**（Postgres）に置きます。

ダッシュボードは **Vercel** にデプロイします。閲覧できる範囲は段階的に分かれていて、誰でも見られるものと、限られた人だけが見られるものを作成予定です。

### 使っているもの

|                |                                                |
| -------------- | ---------------------------------------------- |
| 言語           | TypeScript                                     |
| エージェント   | eve（現在は Claude Code をエンジンとして使用） |
| Web            | Next.js                                        |
| データベース   | Neon (Postgres)                                |
| ホスティング   | Vercel                                         |
| ランタイム     | Node.js 24                                     |
| パッケージ管理 | pnpm                                           |

### ディレクトリ

```
vatesteed/
├── agent/
│   ├── instructions.md   # 常時読み込まれる指示
│   ├── tools/            # lib/ を呼ぶ薄いラッパー
│   ├── skills/           # エージェントのスキル
│   └── schedules/        # スケジュール実行の定義
├── app/                  # Next.js のダッシュボード
│   ├── (public)/         # 誰でも見られる
│   ├── (member)/         # 限定公開
│   ├── (friend)/         # 限定公開（member より広い範囲）
│   └── (private)/        # 開発者専用
├── lib/                  # ツールの実体ロジックとデータベースアクセス
├── docs/                 # 設計ドキュメント
├── AGENTS.md             # エージェントへの指示
└── CLAUDE.md             # AGENTS.md への入口
```
