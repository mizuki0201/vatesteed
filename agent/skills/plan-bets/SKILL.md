# 買い目を組む

**`predict-race` で印を付けてから、レース当日の午前に使う。** 判断の根拠は
[docs/agent-design.md の 5. 買い目を組む](../../../docs/agent-design.md#5-買い目を組む)。

**方針は、当たれば必ずプラスになる組み合わせだけを買い、人気より自分の評価が高い馬にお金を
寄せること。** これまでは◎を軸に3つの券種へ予算を割る形が続き、◎がほとんど1番人気だったため、
当たっても払戻が予算をほとんど上回らなかった（中京2歳ステークスは3つとも的中して+220円）。

## 予算は 2,000円で固定

**レースの格や自信度で変えない。** 恒久の設定。

自信のあるレースで増やすと、当たったときだけ張っていたのか見立てが良かったのかを分けられなく
なる。**予算を固定して初めて回収率を比べられる。** **余らせず、毎レース買う。**

## 1. 当日の午前のオッズをそろえる

**オッズは情報を集める役がそろえて渡す。** Codex から Claude Code を呼ぶ経路では、Codex が
調べてタスクMarkdownに載せ、Claude Code は自分で取りに行かない。Claude Code 単体で進めるときは、
同じセッションが集める役も兼ねる。

そろえるもの:

- 全頭の単勝オッズと人気の順位
- 2. で決める券種の、候補にする組み合わせのオッズ。ワイドと複勝のように幅で出るものは下限
- **確かめた時刻。** 保存するときに使う

**オッズは DB の事実データには入れない。** `entries.win_odds` と `entries.popularity` は確定した
レース後の値の置き場で、当日の午前の値を入れると上書きされて区別できなくなる。使ったオッズは
6. で理由と一緒に残す。

**当日に出走取消・除外があれば、その馬を含む組み合わせを候補から外す。** 印は付け直さない。

## 2. 主に買う券種を1つに決める

**券種は印と展開から選ぶ。** 同じ◎を軸に複数の券種へ予算を割ると、当たっても1つあたりの払戻が
小さくなる。

`race_predictions` にある主な想定の崩れにくさと、`ai_predictions.rationale` にある各馬の見立て
（流れを問わず上位に来るか、どちらかの流れでだけ上位に来るか）を読む。選び方の例（**例示であって
網羅ではない**）:

- ◎が流れを問わず上位に来ると見ていて、相手も絞れる → 単勝か馬連
- 主な想定が崩れる要因が残る、どちらに振れてもおかしくない → 3連複かワイドで、逆に振れた想定で
  上位に来る馬まで相手を広げる

**別の券種を足すのは、主に買う券種では拾えない想定を拾うときだけ**（逆に振れた想定で上位に来る
馬の単勝など）。足すなら、その組み合わせも同じ候補の並びに入れて 4. の判定を通す。

## 3. 印の順位と人気の順位を並べる

**印の順位と、当日の午前の人気の順位を並べる。** 印の順位は◎、◯、▲、△、☆の順。△や☆が
複数なら、`rationale` を読んで評価の高い順に並べる。

- **印の順位が人気の順位より上の馬にお金を寄せる。** 自分の評価が市場より高いところにしか、
  配当の上乗せは無い
- **◎が1番人気なら、◎は軸に残してよいが、相手は印の順位が人気より上の馬へ絞る**
- 印の順位が人気より下の馬は、相手から外すか、候補の並びの後ろへ回す

**オッズを見て印を動かさない。** 印は枠順確定後に固定してある。ここでオッズを見るのは、同じ
見立てに対して配当がいくらになるかを知るためで、馬の能力を測るためではない。

## 4. 候補を並べ、何点まで買うかと金額を機械で出す

**候補の組み合わせを、優先する順に並べる。** 印の順位が人気より上の馬を含むものを先に、その中では
印の上位を含むものを先に置く。

並べた順のオッズを `pnpm bets:allocate` に渡す。

```
pnpm bets:allocate -- --odds 12.3,18.4,25.0,40.1
```

先頭から1つずつ足していき、**どれが当たっても払戻が予算を上回る範囲で、何点まで買えるか**と、
そのときの組み合わせごとの金額が出る。金額は、どれが当たっても払戻がほぼ同じになるように、
配当の低い組み合わせに厚く、高い組み合わせに薄く割られている。合計は必ず2,000円。

- **出た点数より先の候補は買わない。** 上回らなくなった候補を飛ばして後ろを足すこともしない
- 先頭の1点だけでも予算を上回らない（終了コード 1）ときは、2. と 3. に戻って券種か相手を
  考え直す。**判定を通らない組み合わせを、手で金額を変えて通さない**
- **出た点数と金額をそのまま使う。** 点数を減らしたり金額を動かしたりしない。点数を変えたいなら、
  候補の並びそのものを考え直して、もう一度渡す

## 5. 書き込む前に点検し、そのレースの買い目が既にあるか見る

**買い目と理由の案を、保存する前に `verifier` に渡す。** 当たっても払戻が予算を上回らない組み合わせが無いか、
印の順位と人気の順位の判断と使ったオッズがそろっているか、オッズを印の根拠にしていないかを見て
もらう。「崩れている」指摘があれば、保存する前に直す。**保存する前に点検で直すのは、書き直しには
当たらない**（→ [docs/agent-design.md の いつ作るか](../../../docs/agent-design.md#いつ作るか2026-09-19-決定)）。

**`ai_bets` には一意制約が無い。** 1レースに券種違いで複数本あるのが正常なので、制約では
塞げない。**同じレースに2回書くと、前の買い目が残ったまま積み上がる。** 合計金額が二重に
なり、回収率がまるごと壊れる。

```sql
SELECT id, ticket_type, bet_style, total_amount FROM ai_bets WHERE race_id = $1;
```

**行があるなら、入れる前に消す。** 当日の午前に1回だけ組むので、行があるのは、前の実行が途中で
止まったときか、人間が組み直しを指示したときだけ。消すのは `ai_bet_legs` が先（`entry_id` が
RESTRICT なので出走を参照している脚が残っていると消せない）。

```sql
DELETE FROM ai_bet_legs WHERE ai_bet_id IN (SELECT id FROM ai_bets WHERE race_id = $1);
DELETE FROM ai_bets WHERE race_id = $1;
```

**消す操作なので、人間に断ってから実行する。** 買い目は回収率の元になる記録で、消すと戻らない。

## 6. 書き込む

### 買い目

**金額が組み合わせごとに違うので、1組み合わせを1行（単点）で入れる**（→
[docs/data-model.md の 金額の割り方](../../../docs/data-model.md#金額の割り方)）。

1. `ai_bets` に1行（`race_id` / `ticket_type` / `bet_style` は `単点` / `is_multi` は false /
   `unit_amount` は 4. で出た金額 / `combination_count` / `total_amount`）
2. `ai_bet_legs` に列ぶん（`ai_bet_id` / `leg_group` は何列目か / `entry_id`）

**すべての買い方を「列」だけで表す。** 列の数は券種が必要とする頭数と同じ（単勝1・馬連2・
3連複3）。単点なら各列に1頭ずつ。列の中身は `entry_id`。**枠連のときだけ枠番**を入れる
（`entry_id` は null）。

**`combination_count` と `total_amount` は手で数えない。** `expandBet` の計算結果だけを入れる。

```ts
import { expandBet } from "@/lib/bets";

const r = expandBet({
  ticketType: "馬連",
  betStyle: "単点",
  isMulti: false,
  legs: [[7], [11]], // entry_id
  unitAmount: 700,
});
// r.combinationCount / r.totalAmount を ai_bets に入れる
```

`unit_amount` は100円単位。`is_multi` を true にできるのは馬単と3連単だけ。

### 理由

**判断の理由を `ai_bet_rationales` に1レース1行で残す**（→
[docs/data-model.md](../../../docs/data-model.md#ai_bet_rationales)）。振り返りで、買い方の判断が
合っていたかを確かめるために使う。

```sql
INSERT INTO ai_bet_rationales (race_id, odds_checked_at, body)
VALUES ($1, $2, $3)
ON CONFLICT (race_id) DO UPDATE
  SET odds_checked_at = EXCLUDED.odds_checked_at, body = EXCLUDED.body
RETURNING id;
```

`$2` は 1. でオッズを確かめた時刻。`body` に書くもの:

- 主に買う券種と、それを選んだ理由（主な想定の崩れにくさと、各馬の見立てのどこから選んだか）
- 印の順位と人気の順位の並び。どの馬の印の順位が人気より上だったか
- 買った組み合わせごとのオッズ・金額・当たったときの払戻
- 候補にしたが買わなかった組み合わせと、その理由（「◎と◯の馬連は11.2倍で、足すと当たっても
  払戻が2,000円を上回らない組み合わせが出るため買わない」のように、配当の言葉で書く）

**競馬の言葉で書く。** 画面や記事に出しても意味が通る文章にする。保存先の名前、役の名前、
コマンドの名前、作業手順の説明は書かない（→
[docs/agent-design.md の 本文に出さないもの](../../../docs/agent-design.md#本文に出さないもの)）。

## 7. 読み直す

書き終えたら、次を確かめる。

- **保存した列から `expandBet` で組み直して、点数と金額が一致するか。** ここがずれていると
  回収率がまるごと狂う
- そのレースの `total_amount` の合計が2,000円ちょうどか
- `ai_bet_rationales` にそのレースの行があるか

## やらないこと

- **実際に馬券を買わない。** 記録だけ残して擬似的に購入し、回収率を計測する
- **予算を超えない・余らせない。** 2,000円に収める
- **`combination_count` と `total_amount` を手で入れない**
- **当たっても予算を上回らない組み合わせを買わない**
- **オッズを見て印や展開を書き直さない**
- **一度組んだ買い目を、オッズが動いたからといって組み直さない。** 買い目は当日の午前に1回だけ組む
