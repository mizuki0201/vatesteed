# 展開と着順を予想する

**`register-race` で全頭を読み終わってから使う。** 各馬の評価が揃っていない状態で展開を
組むと、先に決めた展開に合う馬を後から探すことになる。判断の根拠は
[docs/agent-design.md の予想の手順](../../../docs/agent-design.md#予想の手順2026-08-15-決定)。

**使うのは枠順が確定したあと。その時点の天気予報と、公表済みの馬場の情報を前提にする。**
ここで出す展開と印は、出した時点で固定する。買い目はレース当日の午前に `plan-bets` が組む
（→ [いつ作るか](../../../docs/agent-design.md#いつ作るか2026-09-19-決定)）。

## 1. 予想時点の前提を置く

**先に予想時刻を1つ決める。** `race_predictions` と `race_prediction_conditions` は
**同じ時点のもの**なので、[両方に同じ値を渡す](../../../docs/data-model.md#race_prediction_conditions)。

- **`now()` を使わない。** 文を投げるたびに別の時刻が入り、展開の見立てと、その見立てが乗って
  いた前提が、違う時点のものとして残る
- 決めた時刻は `--params` に入れて渡す。**`ON CONFLICT` の側でも `EXCLUDED.predicted_at` を
  使い、入れ直したときに `VALUES` と同じ値になるようにする**

**展開の見立てと、その見立てが何に乗っていたかは別のもの。** 前提は調査資料から
`race_prediction_conditions` にまとめ、展開の本文には混ぜない（→
[docs/agent-design.md](../../../docs/agent-design.md#予想時点の前提とレース後の実績を混ぜない)）。

```sql
INSERT INTO race_prediction_conditions (race_id, predicted_at, track_division, body, author)
VALUES ($1, $2, $3, $4, 'AI')
ON CONFLICT (race_id) DO UPDATE
  SET predicted_at = EXCLUDED.predicted_at, track_division = EXCLUDED.track_division,
      body = EXCLUDED.body, author = 'AI'
WHERE race_prediction_conditions.author = 'AI'
RETURNING id;
```

- 入れるのは**予想を出す時点で分かっていたことだけ。** コース区分、開催がどこまで進んでいるか、
  予報、馬場の見込み、公表済みの数値
- **取れなかったものは「取れなかった」と `body` に書く。** 空けたままにすると、調べていないのか
  調べて無かったのかが分からない。**推測値で埋めない**
- **開催回と日目は `races` にあるので書き直さない。** そこから読めないこと（開催が進んで内が
  荒れてきた、など）を書く
- **レース後にここへ手を入れない。** 実際の馬場と天気は `races.track_condition` `races.weather`
  に入る

## 2. 展開を組ませる（`pace-analyst`）

**展開は `pace-analyst` に組ませる。** 手順と出す形は
[pace-analyst の指示](../../../agent/subagents/pace-analyst/instructions.md)が正本。
基準のペースを置き、各馬の前に行く力を位置と流れの組で読み、前の集団の頭数を1つに決めてから
ペースの幅を出す。主な想定と、ペースが逆に振れた想定、主な想定がどれだけ崩れにくいかを返す。

呼ぶときに渡すもの（役は会話履歴を見ないので、全部メッセージに載せる）:

- レースID。予想時点の前提と各馬の評価は DB にあるので、役が自分で引く（DB から読める内容を
  貼り付けない → [呼び出すときに渡すもの](../../../docs/agent-design.md#呼び出すときに渡すもの)）
- 調査資料のうち DB に無いもの。`register-race` の 1. で集めた、基準にするペースの材料（そのレースの
  近年の前半タイム・頭数・先頭と前の集団にいた馬。無ければ同じコース・同じクラスのもの）、過去の
  出走の前半タイムと頭数（DB にラップが無いレース、出走が全頭登録されていないレースのもの）、
  馬具の変更
- 全頭の評価を読み終えていること

**Codex から Claude Code を呼ぶ経路ではサブエージェントを起動しない。** そのときは、同じ
セッションが `pace-analyst` の指示を読み、その順序どおりに組む。

### 展開を保存する前に `verifier` で点検する

**返ってきた展開を、保存する前に `verifier` へ渡す。** 印は展開の上に乗るので、ここで止めた方が
直す範囲が小さい。渡すのは展開の返答（まだ保存していないので、本文そのもの）と、その根拠になった
評価の対象（どのレースか）。見るのは
[検証の手順の観点](../../../docs/agent-design.md#観点)のうち展開に関わるもの（先頭に立つ意思から
ペースを決めていないか、前の集団の頭数を決めてあるか、逆に振れた想定と崩れにくさの判断があるか、
など）。

- 「崩れている」指摘があれば `pace-analyst` へ差し戻す（Codex からの経路では、同じセッションで
  組み直す）
- 「弱い」「気になる」は、受けるかどうかをここで決める

### 展開を保存する

**点検を通った「保存する本文」だけを書く。** 「保存しないメモ」は書かない。

```sql
INSERT INTO race_predictions (race_id, body, author, predicted_at)
VALUES ($1, $2, 'AI', $3)
ON CONFLICT (race_id) DO UPDATE
  SET body = EXCLUDED.body, author = 'AI', predicted_at = EXCLUDED.predicted_at
WHERE race_predictions.author = 'AI'
RETURNING id;
```

`$3` は 1. で決めた予想時刻。`author` は `AI`、人間と詰めたなら `対話`。

**`rowCount` が 0 で返ったら、その行は人間か対話が書いたもの。**書き直さず、前の見方・
新しい見方・何がどう変わるのかを添えて人間に確認する。

## 3. 印をつける

**全頭に行を作る。** 無印は `mark_id` を null にする。印を付けない馬にも、なぜ付けないかを
`rationale` に書く。

### 印を付ける頭数を先に決める

**◎、◯、▲、△、☆の合計は、出走頭数の約4割とし、最大でも7頭にする。**
18頭立てでは◎1頭、◯1頭、▲1頭、△2〜3頭、☆1〜2頭を基準にし、合計は最大7頭とする。
◎、◯、▲は各1頭まで。出走頭数が少ないときは△と☆を評価順に減らす。

保存前に、その時点で`status = '出走'`の出走頭数をDBから数える。

```sql
SELECT count(*) AS entry_count
FROM entries
WHERE race_id = $1 AND status = '出走';
```

印を付けられる頭数は`min(7, round(entry_count * 0.4))`。出走頭数の4割を最も近い整数へ丸める。
18頭立てなら最大7頭、12頭立てなら最大5頭、11頭立てなら最大4頭になる。これは上限であって、
上限まで印を付ける目標ではない。
全頭の評価を並べたあと、上限を超えた分を無印へ戻してから保存する。消しの「ー」は買い目の候補を
示す印ではないので、この合計には含めない。

### 2つの想定の両方に全頭を当てはめる

**1本の想定に印を乗せない。** 前半のペースの想定は外れることが多く、想定に合うことを理由に
上げた馬ほど外れていた（理由は
[docs/agent-design.md の 1本の想定に印を乗せない](../../../docs/agent-design.md#1本の想定に印を乗せない2026-09-19-決定)）。

1. **全頭について、根拠を2つに分けて並べる。**
   - 展開に左右されない根拠: 能力、実績、違う流れのレースでも結果を出していること
   - 特定の流れでだけ成り立つ根拠: 「中盤が緩めば」「前が競り合えば」のように、その想定が
     当たったときだけ効くもの。`pace-analyst` が返した全頭の向き不向きを使う
2. **それぞれの想定で、全頭を上位に来る見込みの順に並べる。** 各馬の能力と、その想定での
   向き不向きを合わせて決める。**その想定の並びで、印を付けられる頭数の上限までに入る馬を、
   その想定で上位に来る馬とする**（18頭立てなら各想定の上から7頭）
3. **印を付ける順に全頭を並べる。** どちらの想定で上位に来るかで段に分け、`pace-analyst` の
   崩れにくさの判断に応じて段の順を決める。どちらの想定でも上位に来ない馬には印を付けない。

| 崩れにくさの判断 | 印を付ける順 |
| --- | --- |
| 崩れにくい | 両方の想定で上位に来る馬と、主な想定でだけ上位に来る馬 → 逆に振れた想定でだけ上位に来る馬 |
| 崩れる要因が残る | 両方の想定で上位に来る馬 → 主な想定でだけ上位に来る馬 → 逆に振れた想定でだけ上位に来る馬 |
| どちらに振れてもおかしくない | 両方の想定で上位に来る馬 → 主な想定でだけ上位に来る馬と、逆に振れた想定でだけ上位に来る馬 |

4. **同じ段の中は、展開に左右されない根拠を先に比べ、並んだときに想定での向き不向きで分ける。**
5. **並べた順に、◎、◯、▲を1頭ずつ付け、続く馬に△、その後ろに☆を付ける。** △と☆の頭数は
   上の基準（18頭立てなら△2〜3頭、☆1〜2頭。出走頭数が少なければ△と☆を減らす）に従い、
   印を付けられる頭数の上限で止める。並べた馬がそれより少なければ、並べた馬までで止める

**どの印でも同じやり方で決める。** 印の位置によって展開を使ったり使わなかったり、特定の印だけ
並べ方を変えたりしない。主な想定が崩れやすいほど、主な想定でだけ上位に来る馬は並びの後ろへ下がる。
2026年8〜9月の7レースで外れていたのは、この馬を上の印にした形だった。

**経験していない条件（初めての距離・馬場・競馬場など）を、印を上げる理由にも下げる理由にも
しない。** 結果の振れ幅が大きい馬として扱い、血統の評価（`pedigree_notes`）や、似た条件で実際に
示した内容があればそれで補う。馬の総合分析で、経験していないことを不安や限界として書かないのと
同じ考え方（→ [docs/analysis-quality.md](../../../docs/analysis-quality.md#書かない内容)）。

### `rationale` に書くこと

**その馬を読んだ結果のうち、印を決めた部分**を書く。`entry_notes` の写しにしない。
**画面に出る本文なので、競馬の言葉で書く。** 手順の段や表の名前は書かない（→
[docs/agent-design.md の 本文に出さないもの](../../../docs/agent-design.md#本文に出さないもの)）。

- **展開に左右されない根拠と、特定の流れでだけ成り立つ根拠を分けて書く**
- どの流れで上位に来ると見たかを、流れの言葉で書く（「前半が速くなっても遅くなっても上位に
  来る」「前半が緩んだときだけ上位に来る」）
- 条件替わり、斤量、乗り替わり、叩きかどうかのうち、印に効いたもの

### 印を保存する前に `verifier` で点検する

**全頭の印と理由の案を、保存する前に `verifier` に渡す。** 渡すのは展開（保存済み）と、印と理由の
案。印が1本の想定に乗っていないか、経験していない条件で印を動かしていないか、上の並べ方から
外れていないかを見てもらう。「崩れている」指摘があれば直してから保存する。保存する前に点検で
直すのは、書き直しには当たらない。

### 印を保存する

書き込む先は `ai_predictions`（`entry_id` ごとに1行、`predicted_at` は now()）。`mark_id` は
`marks` から記号で引く（◎ 本命 / ◯ 対抗 / ▲ 単穴 / △ 連下 / ☆ 大穴 / ー 消し）。

保存後に全頭の行数と、◎、◯、▲、△、☆を付けた頭数を読み直す。後者が上限を超えていたら完了に
しない。

```sql
SELECT
  count(*) AS prediction_count,
  count(*) FILTER (WHERE m.symbol IN ('◎', '◯', '▲', '△', '☆')) AS marked_count
FROM entries e
JOIN ai_predictions p ON p.entry_id = e.id
LEFT JOIN marks m ON m.id = p.mark_id
WHERE e.race_id = $1 AND e.status = '出走';
```

## 4. 渡す

**買い目はここでは組まない。** レース当日の午前に、その時点のオッズを見て `plan-bets` が組む。
印の段階で「厚く買う馬」を決め込まない。

## やらないこと

- **各馬を読まずに展開から入らない。** 順序を逆にしない
- **人気とオッズを根拠に印を決めない。** 人気は結果であって能力ではない。オッズを見るのは
  買い目を組むときだけ
- **1本の想定に印を乗せない。** 印の位置によって展開を使い分けない
- **裏の取れていない数値を判断の柱にしない**（[register-race](../register-race/SKILL.md) の裏取り）
- **出した展開と印を、当日の馬場やオッズを見てから書き直さない。** 展開と印は枠順確定後の時点で
  固定する。当日の話は対話として扱う（[docs/product.md](../../../docs/product.md#2-レースを予想する1の特殊な形)）
