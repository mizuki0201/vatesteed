# レースを1つ登録し切る

**予想を始める前に、材料を揃えて DB に入れるところまでを通す進行役。** 判断の根拠は
[docs/agent-design.md の予想の手順](../../../docs/agent-design.md#予想の手順2026-08-15-決定)。

このスキルが終わったら `predict-race` へ渡す。**各馬を読み終わるまで展開を組み始めない。**

## 1. レースを特定する

呼び方の揺れ（「春天」「宝塚の」）は正式名称に直す。表記は半角の括弧・数字・英字で、
空白を入れない（[docs/data-model.md](../../../docs/data-model.md#表記ルール)）。

情報源から取るもの: 開催回・日目、レース番号、格、負担重量の条件、コース（競馬場・芝ダート・
距離・回り・内外）、枠順確定後の出走メンバー、天気予報。

## 2. 土台を登録する

**必ず「もう居るか」を名前で探してから作る。** 馬名には UNIQUE を張っていないので、探さずに
入れると同じ馬が二重に登録され、評価が二手に分かれて静かに壊れる。

登録の順序は `courses` → `races` → `trainers` → `jockeys` → `horses` → `entries`。
外部キーの向きがこの順になっている。

- SQL は `pnpm db:query`。値は必ず `--params` で渡す
- 長い日本語や引用符が入るものは `tmp/` に SQL ファイルを書いて `--file` で渡し、**書き終わったら消す**
- `entries` は枠順確定時に埋まる分（枠番・馬番・斤量・騎手・厩舎）だけ入れる。
  着順・人気・オッズ・通過順は**レース後**の列なので、ここでは触らない

## 3. 出走馬を1頭ずつ読む

**ここが本体。** 全頭ぶん、次の2つを**両方**やる。

| | 何を |
| --- | --- |
| DB を引く | その馬の過去の出走とその評価、血統・騎手・厩舎・コースの評価 |
| 検索する | **前走から今日までに起きたこと。** 調整過程、追い切り、陣営のコメント、乗り替わりの経緯、放牧や輸送 |

**DB が育つまでは検索を丁寧にやる。** 蓄積が薄いうちは材料のほとんどが外にしかない。
手間が多いことを理由に省略しない。

読ませる先は対象ごとの分析する役（`entry-analyst` ほか）。**1回の呼び出しで1つの出走**なので、
複数の出走を読ませるなら回数を分けて並列で呼ぶ。呼ぶときに渡すのは**どの対象かと、人間から出た
観察・コメントだけ**。DB から読めるものは役が自分で引く。

### このレースが「叩き」かどうかも見る

**「叩き」とは、そのレースを本番と位置づけず次の目標への調整として使うこと。** 仕上げを
100%にしないので、能力どおりに走らない。

- 陣営が明確にコメントしていれば、それに従う
- コメントが無いときは、**陣営の立場に立って先のローテーションを組み立てて**逆算する
- 分からないなら**分からないと書く。** 推測で決めつけて能力を割り引かない

## 4. 過去の出走をどこまで入れるか

**予想の対象レースは全頭。過去のレースは、読むと決めた出走だけ。**

- 相手関係は、役を呼ぶときのメッセージに着順表として渡す
- **「DB だけを見ると相手関係が分からない」ことを評価の本文に残す**
- 同じレースを何度も参照するようになったら、そのとき全頭を入れる。先回りしない

## 5. 裏取り

**2回試して確からしい値が取れなければ、諦めて「取れなかった」と残す。**

- 数値が判断の柱になるときは、別の情報源で突き合わせる
- **同じページの他の項目が壊れていたら、そのページ全体を疑う**（実在しない馬名・騎手名など）
- 取れなかったことを評価の本文に書き、**その数値を判断の柱に据えない**

## 人間に聞くこと

**承認は求めない。** 聞くのは人間にしか無いものだけ — 映像を見て気づいたこと、コメントの含意、
陣営の事情、遠征の経緯。**問いを出しても止まらず、分かる範囲を書いて先へ進む**
（[docs/product.md](../../../docs/product.md#人間に何を聞くか)）。
