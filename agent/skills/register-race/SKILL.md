# レースを1つ登録し切る

**予想を始める前に、材料を揃えて DB に入れ、各馬を読み終わるまでを通す進行役。** 判断の根拠は
[docs/agent-design.md の予想の手順](../../../docs/agent-design.md#予想の手順2026-08-15-決定)。

このスキルが終わったら `predict-race` へ渡す。**各馬を読み終わるまで展開を組み始めない。**

## この手順の担当は2つに分かれている

**0 から 2 と 4・5 は、情報を集める役の担当。3 は分析する役の担当。** 現在の Codex から
Claude Code へ渡す経路では、Codex が 0 から 2 と 4・5 を終えてから Claude Code へ渡す
（[docs/claude-code-bridge.md](../../../docs/claude-code-bridge.md)）。本人が Codex 単体、
Claude Code 単体を指定したときは、同じ実行元が上から順に行う。

**競馬の分析として起動された Claude Code は、事実データを登録できない。** 自分で外部サイトや
動画を見に行かず、`pnpm db:query` から馬・レース・出走・コメントなどを更新しない。3 に入る前に
登録済みかを確かめ、足りなければ対象・必要な事実・その事実を使う判断をタスクMarkdownの
「未登録・未分析」へ書いて進行役へ返す。進行役が登録し終えたら、同じ実行を再開して続ける。

## 0. 待っているメモを見る（情報を集める役）

**そのレースに関係する未処理・保留のメモを先に引く。** 外で見かけた話の多くは「今週のあの馬」で、
ここを通さないと毎回取りこぼす。手順は `intake-memos`。

```
pnpm db:query "SELECT id, body, source, status FROM memos WHERE status = ANY($1::text[]) ORDER BY created_at ASC" --params '[["未処理","保留"]]'
```

**このレースに関係しないものは、そのまま残す。** 出走を登録したあとで置けるようになるものが
あるので、**2 を終えたらもう一度見る。**

## 1. レースを特定する（情報を集める役）

呼び方の揺れ（「春天」「宝塚の」）は正式名称に直す。表記は半角の括弧・数字・英字で、
空白を入れない（[docs/data-model.md](../../../docs/data-model.md#表記ルール)）。

調査資料から確認するもの: 開催回・日目、レース番号、格、負担重量の条件、コース
（競馬場・芝ダート・距離・回り・内外）、枠順確定後の出走メンバー、天気予報。

**あわせて、予想時点の馬場の前提も集める。** コース区分（Aコース・Bコースなど）、開催が
どこまで進んでいるか、馬場の見込み、公表済みの数値。**置き先は `race_prediction_conditions` で、
入れるのは `predict-race`**（→ [docs/agent-design.md](../../../docs/agent-design.md#ラップと予想時点の前提2026-08-17-決定)）。
**取れなかったものは、取れなかったと分かるようにしておく。推測で埋めない。**

## 2. 土台を登録する（情報を集める役）

**必ず「もう居るか」を名前で探してから作る。** `horses` `jockeys` `trainers` には UNIQUE を
張っていない（競走馬名は引退から一定期間で再使用できるため）。**探さずに入れると同じ馬が
二重に登録され、評価が二手に分かれて静かに壊れる。** 索引は張ってあるので探すのは速い。

`races` も、**`race_number` が取れないレース（海外・地方）は自然キーの守りが効かない。**
番号が null の行どうしは重複して入るので、こちらも登録の前に名前と日付で探す。

登録の順序は `courses` → `races` → `trainers` → `jockeys` → `horses` → `entries`。
外部キーの向きがこの順になっている。

**入れるのは、今回の分析対象に直接属するものだけ。** 予想の対象レースは全出走が分析対象なので
全頭を入れる。調査の途中で出てきた関連情報は、タスクMarkdownの「事実の登録範囲」で登録すると
決めたものだけを入れる（→
[docs/agent-design.md](../../../docs/agent-design.md#事実をdbへ登録する範囲2026-09-06-決定)）。

- SQL は `pnpm db:query`。値は必ず `--params` で渡す
- 長い日本語や引用符が入るものは `tmp/` に SQL ファイルを書いて `--file` で渡し、**書き終わったら消す**
- `entries` は枠順確定時に埋まる分（枠番・馬番・斤量・騎手・厩舎）だけ入れる。
  着順・人気・オッズ・通過順は**レース後**の列なので、ここでは触らない
- 馬を新しく登録するときは、現役か引退かも調査資料で確認する。引退が確認できた馬だけ
  `horses.retired_at` を入れ、確認できなければ空のままにする
- 全頭ぶんの `entries` を入れ終えたら、対象レースの `entry_list_complete` を true にする。
  これはレース一覧に出してよい出馬表が揃った印である。馬の分析に伴い過去レースの出走を
  一部だけ登録するときは、true にしない

## 3. 出走馬を組ごとに読む（分析する役）

### 登録済みかを先に確かめる

**読み始める前に、対象レースの `entries` が全頭ぶん入っているか、各馬の過去の出走が依頼された
範囲まで入っているかを DB で確かめる。** タスクMarkdownの「事実の登録範囲」に進行役が決めた
登録の範囲が、「事実の登録結果」に登録して読み直した結果が書いてある。

**DBに無いものが、すべて不足ではない。** 過去のレースの他馬、その払戻、先祖の馬は参照だけと
決まっていることが多く、材料は調査資料の側にある。**登録する範囲に入っているのに登録されて
いないものだけ**を、**自分で登録せず**、対象・必要な事実・その事実を使う判断とともに
「未登録・未分析」へ書いて進行役へ返す。揃っている範囲だけで読み進められるなら、読める範囲を
先に進めてから返してよい。

### 分析の範囲を先に確定する

馬を読む前に、**過去の出走を何回精査するか**を人間に確認する。これは分析の深さを決める依頼条件で、
レースごとの固定値ではない。指定が無ければ、過去4回でよいかを聞く。回答が得られるまで、馬の分析を
始めない。

あわせて、何頭を1組として扱うかを確認する。人間から別の指定が無ければ2頭を1組にする。組の数、
精査する過去の出走数、同時に動かす分析役数を実行記録に残す。

**過去の出走数が増えても、役を出走ごとに増やさない。** 1頭を担当する実行が、指定された出走を
まとめて読み、出走ごとの評価を残す。Phase 1 の既定では、Claude Code の主たる実行がそのまま
処理し、子エージェントを起動しない。並列にする場合も、組に含めた馬の数を超える分析役を起動しない。

組ごとに、指定された過去の出走数ぶんの `entry_notes`、必要な `pedigree_notes`、馬の見立てが
揃ったことをDBで確かめ、タスクMarkdownの「対象ごとの進捗」「DBへの保存結果」「現在地」を
更新してから次の組へ進む。途中終了、空の出力、利用枠エラーは未完了であり、同じ実行記録を再開する。
同じ失敗を繰り返して結果が増えない場合は、停止理由と再開条件をMarkdownへ記録し、新しいClaude
Codeセッションでやり直さない。

### 読む内容

**ここが本体。** 全頭ぶん、次の2つを**両方**やる。

| | 何を |
| --- | --- |
| DB を引く | その馬の過去の出走とその評価、血統・騎手・厩舎・コースの評価 |
| 調査資料を読む | **前走から今日までに起きたこと。** 調整過程、追い切り、陣営のコメント、乗り替わりの経緯、放牧や輸送 |

**DB が育つまでは調査資料を丁寧に読む。** 蓄積が薄いうちは材料のほとんどが外にしかない。
手間が多いことを理由に省略しない。

### 騎手と陣営のコメントは `entry_comments` に入れる（情報を集める役）

**調査資料にあるコメントを、評価の本文や役へのメッセージだけで扱わない。** 発言のたびに1行
入れる。今回のレースに向けて出たものは `race_phase` が `レース前`。読み方の基準は
[docs/agent-design.md](../../../docs/agent-design.md#コメントをどう読むか2026-08-17-決定)。

**入れるのは 2 と同じく情報を集める役で、分析する役は読むだけ。** 分析の途中で入っていない
発言に気づいたら、自分で入れずに「未登録・未分析」へ書いて返す。

```sql
INSERT INTO entry_comments
  (entry_id, race_phase, speaker_role, speaker_name, spoken_on, summary, interpretation, source, author)
VALUES ($1, 'レース前', $2, $3, $4, $5, $6, $7, 'AI')
RETURNING id;
```

- **入れるのは要約と、そこから読み取った含意。** 取得したページの本文をそのまま入れない
  （`summary` は400字まで）。要約と含意は別の列に分ける
- **取れなかったものは空のままにする。** 発言者の名前も日付も、推測で埋めない
- **入れる前に、同じ出走・同じ時点・同じ発言者の行が無いかを探す。** 一意制約が無いので、
  二重登録はここでしか防げない
- **登録するのは情報を集める役。** 分析する役には読ませるだけで、入れさせない
- **コメントを入れたことを理由に評価を書き換えない。** 表明された意図は事実ではないので、
  `*_notes` を動かすかどうかは読んだ結果から別に決める
- 過去の出走について出たコメントも、その出走が登録済みなら同じ形で入る。登録していない出走の
  ぶんは置き場が無いので、残したいなら先にその出走を登録する

### 読む順序は「出走 → 血統 → 馬」

**1頭につき3段階ある。途中で終わらせない。** これは評価の内容と保存先の順序であり、
Claude Code の呼び出し回数を定めるものではない。

1. **`entry-analyst`** — その馬について指定された過去の出走を読み、出走ごとに `entry_notes` に残す。
   分析の実行は、指定された出走をまとめて扱う
2. **`pedigree-analyst`** — 血統から適性の素地を読み、`pedigree_notes` に残す
3. **`horse-analyst`** — 1 と 2 を突き合わせて「この馬はどういう馬か」を出す

**`entry-analyst` は、1つの出走の中で起きた事実とそこからの読みまでを残す。** 出走をまたいで
馬の性質をまとめない。**次の出走での扱いも AI から書かせない。** 人間がその出走の解釈として
明示したときだけ、誰の解釈かが分かる形で残す（→
[docs/agent-design.md](../../../docs/agent-design.md#1つの出走から結論にしてよい範囲2026-09-01-決定)）。
**複数の出走と血統を総合するのは 3 だけ。** ここでは1頭の全体を読んで見立てを返す。レース後の
振り返り（`review-race`）でも `horse-analyst` を呼ぶが、そちらでは今回の結果で結論が変わった
項目だけを差し替える（→
[docs/analysis-quality.md](../../../docs/analysis-quality.md#レース振り返り後の更新)）。

**3 は必ず最後。** `horse-analyst` は「`pedigree_notes` があれば読む。自分で血統を遡らない」と
決めてあるので、**血統が空のまま呼ぶと血統の話が丸ごと抜けた見立てが返る。** 実績と血統を
突き合わせて重み付けするのもこの役なので、両方が揃っていないと仕事が成立しない。

**1 と 2 の間に依存は無い**（2026-08-16 訂正）。`pedigree-analyst` は実績を見ないと決めたため
（→ [docs/agent-design.md](../../../docs/agent-design.md#血統評価はその馬の血統だけで決まる2026-08-16-訂正)）。
書き込む先も重ならないので、**1 と 2 は並べて呼んでよい。**

**`pedigree-analyst` に渡すのは、どの馬かだけ。** 戦績・前走・実績はもちろん、**今回のレースや
条件も渡さない。** 血統評価はその馬の血統だけで決まり、**何のために呼ばれたかで内容が変わっては
いけない**。条件を渡すと、渡した条件に寄せた本文が書かれる。

**血統は1頭につき一度書けば、次のレースでもそのまま使える。** 毎回書き直すものではない。

`horse-analyst` は **`horse_notes` を自分で書かない。** 対話で作ると決めた評価なので、
見立てを返してくる。**それを受け取ってオーケストレーターが書き込む**（`author` は `AI`。
人間とすり合わせたなら `対話`）。

**書き込む前に実行確認を確かめる。** 一般ルールと参考例を読んだことが `## 保存しないメモ` に
無い返答は、そのまま保存しない（→
[docs/analysis-quality.md](../../../docs/analysis-quality.md#実行時の確認)）。

```
pnpm analysis:confirm -- --kind horse --response <返答を保存したファイル>
```

**`entry-analyst` と `pedigree-analyst` は自分で書き込む役なので、書き込む前に自分で同じ確認を
通す。** 受け取った側でも、返ってきた内容に実行確認があることを見る。通っていなければ、その
評価を使わずに役へ差し戻す。

**書き込むのは、返答の `## 保存する本文` の中身だけ。それが `body` に入る。**
`## 保存しないメモ` は書き込まず、次に何をするかを決めるために読む（→
[docs/agent-design.md](../../../docs/agent-design.md#評価の本文と返すだけのメモ2026-08-18-決定)）。
足りなかった材料・他の役へ渡すもの・調べ方の顛末はメモの側にあるので、**そこから次の呼び出しと、
進行役へ返す不足を決める。** 2つを混ぜて書き込むと、内部の作業情報がそのまま人の読む画面に出る。

**`## 保存する範囲` を返してくるのは血統・産駒だけ。** そこは `scope` に入る保存値で、メモでは
ない（下記「血統・騎手・厩舎・コースも読ませる」）。

呼ぶときに渡すのは**どの対象か、調査資料、人間から出た観察・コメント**。役は DB とその資料を
読む。**役は外部サイトや動画を見に行かない。** 材料不足が判断に効くときは、不足した事実を
返してくるので、それを「未登録・未分析」へまとめて進行役へ返す。**人間の側にしか無いもの**
（映像を見た印象、コメントの含意、陣営の事情）も、渡さないと使われない。

### 血統・騎手・厩舎・コースも読ませる

**分析する役は8つとも中身が書いてある**（2026-08-16 時点）。出走と馬に加えて、必要なものを
呼ぶ。`pedigree-analyst` `jockey-analyst` `trainer-analyst` `course-analyst` は**自分で
評価テーブルに書く**ので、オーケストレーターは受け取るだけでよい。

**`pedigree-analyst` だけは返し方が3つに分かれる。** `## 保存する本文` が `body`、
`## 保存する範囲` が `pedigree_notes.scope` と `progeny_notes.scope` で、**どちらも役が自分で
書き込む。** 受け取った範囲を本文へ足さない。**書き込まないのは `## 保存しないメモ` だけ。**

**`pedigree-analyst` を呼ぶ前に、血統の材料が揃っているかを確かめる。** 見る先は `horses` の
`sire_id` `dam_id` だけではない。**先祖が `horses` に入っていなくてよい。** 対象馬の血統分析だけを
理由に先祖を登録しないと決めてあるので、調査資料に5〜6代ぶんの血統があれば呼べる（→
[docs/agent-design.md](../../../docs/agent-design.md#血統で参照する先祖は分析対象でなければ登録しない)）。

- **確かめるのは、調査資料に父・母・母父と、牝系・クロスをたどれるだけの血統があるか**。
  既に登録済みの先祖があれば、その `progeny_notes` も併せて渡す
- **足りないのは資料の側なので、返すのは「登録してほしい馬」ではなく「たどれなかった血統」**。
  対象・必要な事実・その事実を使う判断を「未登録・未分析」へ書いて進行役へ返す
- 先祖の馬自体を分析対象にすると決めた場合だけ、その馬を独立した対象として登録する。対象馬の
  血統を読むついでに広げない

**役は調査資料と登録済みの事実を使う**（2026-09-05 更新）。調整過程や血統など、DB に無い材料は
情報を集める役が先に集めて渡す。**登録するのは分析対象に直接属する事実だけで、それ以外は資料の
まま渡す。** **分析する役も、それを呼ぶ側も、自分で検索しない。** 人間から出た観察・コメントも
渡さないと使われない。

### このレースが「叩き」かどうかも見る

**「叩き」とは、そのレースを本番と位置づけず次の目標への調整として使うこと。** 仕上げを
100%にしないので、能力どおりに走らない。

- 陣営が述べているなら、まずそれを材料にする。**ただし述べられた意図であって、仕上げの事実では
  ない。** 調整過程や実際の走りと突き合わせる
- コメントが無いときは、**陣営の立場に立って先のローテーションを組み立てて**逆算する
- 分からないなら**分からないと書く。** 推測で決めつけて能力を割り引かない

## 4. 過去の出走をどこまで入れるか（情報を集める役）

**予想の対象レースは全頭。馬を読むために過去のレースを参照するときは、対象馬の出走だけ。**

- 相手関係は、役を呼ぶときのメッセージに着順表として渡す
- **相手関係をどこまで確かめられたかを、評価の本文に残す。** ただし
  [競馬の言葉で書く](../../../docs/agent-design.md#評価の本文と返すだけのメモ2026-08-18-決定)。
  「中身まで読んだのは4頭で、残りは着順を見ただけ」のように書き、蓄積の側の事情を本文に持ち込まない
- **この経路では、同じ過去レースの他馬・出馬表・`entry_list_complete` に触れない。** 何度
  参照しても、過去レースの全頭を登録しない
- **その過去レースの `race_payouts` も入れない。** 払戻を入れるのは、そのレースの振り返りや
  買い目の答え合わせで要るときだけ（→
  [docs/data-model.md](../../../docs/data-model.md#確定払戻)）
- 過去レースの出馬表を登録するのは、**そのレース自体を分析すると決めたときだけ**。馬を読む途中で
  レース分析を始めない
- **調べた内容は捨てない。** 他馬・払戻・血統など登録しないものは、タスクMarkdownの「事前調査」と
  「参照元」へ要約して残し、分析する役へ渡す

## 5. 裏取り（情報を集める役）

**収集を担う役が2回確かめても確からしい値が取れなければ、諦めて「取れなかった」と残す。**

- 数値が判断の柱になるときは、別の情報源で突き合わせる
- **同じページの他の項目が壊れていたら、そのページ全体を疑う**（実在しない馬名・騎手名など）
- 取れなかったことを評価の本文に書き、**その数値を判断の柱に据えない**
