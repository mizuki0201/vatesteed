# レースを1つ振り返り切る

**終わったレースの結果を取り込み、そのレースと各出走の評価を残し切るまでを通す進行役。**
判断の根拠は
[docs/agent-design.md の振り返りの手順](../../../docs/agent-design.md#振り返りの手順2026-08-16-決定)。

**振り返りで扱うのは、そのレース、そのレースの出走、そして出走した馬のまとめのうち今回の結果で
結論が変わる項目まで。** 複数の出走を総合する `horse-analyst` も呼ぶが、**まとめ全体を書き直させ
ない。** 変わった項目だけを差し替える（→
[docs/analysis-quality.md](../../../docs/analysis-quality.md#レース振り返り後の更新)）。

**予想とは順序が逆になる。** 予想では出走から馬へ積み上げたが、振り返りは**レース全体の評価を
先に出して、そこから降ろす**。ペースと馬場が分からないまま1つの出走を読むと、着順を説明する
だけの話になる。

**1 は情報を集める役、2 から 7 は分析する役の担当。** 現在の Codex から Claude Code へ渡す
経路では、Codex が結果・ラップ・レース後のコメントと、買い目の答え合わせに必要なら払戻を登録して
読み直してから Claude Code へ渡す（[docs/claude-code-bridge.md](../../../docs/claude-code-bridge.md)）。本人が Codex 単体、
Claude Code 単体を指定したときは、同じ実行元が上から順に行う。

**競馬の分析として起動された Claude Code は、事実データを登録できない。** 結果が入っていない
ことに気づいたら、自分で調べて入れず、必要な事実と、その事実を使う判断をタスクMarkdownの
「未登録・未分析」へ書いて進行役へ返す。進行役が登録し終えたら、同じ実行を再開して続ける。

**返す前に、タスクMarkdownの「事実の登録範囲」を見る。** 参照だけと決まっている関連情報は、
DBに無いのが正しい状態なので、登録を求めない。**登録する範囲に入っているのに入っていないもの
だけを返す。**

```
1. 結果を取り込む
2. レースを評価する        ← race-analyst
3. 出走を1つずつ読み直す    ← entry-analyst
4. 人間の観察と照合する
5. 馬のまとめの差分を作る    ← horse-analyst
6. 予想と買い目の答え合わせ
7. 検証して馬の差分を反映する ← verifier / オーケストレーター
8. 気づいたことを挙げる
```

## 1. 結果を取り込む（情報を集める役）

**ここが終わるまで 2 へ進まない。** 通過順と上がり3Fが入っていない状態で評価すると、印象で
書くことになる。分析する役は、この5か所が埋まっていることを DB で確かめてから 2 へ進む。

**振り返るレースは全出走が分析対象なので、全頭ぶんを埋める。** `race_payouts` は、買い目の
答え合わせを行う場合だけ入れる。**馬を読むために過去のレースを参照しただけのときは、
そのレースの払戻を入れない**（→
[docs/agent-design.md](../../../docs/agent-design.md#事実をdbへ登録する範囲2026-09-06-決定)）。

埋めるのは5か所。

| 入れる先 | 何を |
| --- | --- |
| `entries` | `finish_position` `margin` `popularity` `win_odds` `finish_time_ms` `last_3f_ms` `corner_positions` `body_weight` `body_weight_diff` |
| `races` | `weather` `track_condition` |
| `race_laps` | **区間ごとのラップ。** 何区間目か・その区間の距離・その区間の時計 |
| `race_payouts` | **確定払戻。** 券種ごとに、当たった組み合わせ・100円あたりの払戻金・人気 |
| `ai_bets` | 予想時に作った買い方ごとの `payout` と、取消・除外があれば `refund` |

- **走らなかった馬は `status` を直す**（取消・除外・中止・失格）。着順が入るのは `出走` の
  ときだけで、CHECK 制約が効いている。**人気とオッズには同じ縛りが無い**ので、中止・失格でも
  分かっているなら入れる
- **降着があれば、入れるのは降着後の確定着順**
- `margin` は「クビ」「1.1/2」のような文字のまま入れる。**1着は空**
- `race_payouts` の `combination` は、**枠連だけ枠番、それ以外は馬番**。同着があると同じ券種で
  複数行になる
- **確定払戻は回収率の計算には使わない**（回収率は `ai_bets` から出す）。画面に出すためと、
  検算のために入れる。**買い目の答え合わせを含まない依頼では入れなくてよい**
- `ai_bets` の的中判定と払戻額は `lib/bets` で出す。外れた買い方の `payout` は 0 にし、
  **空のままにしない**。取消・除外があった買い方は `refund` も入れる。予想が無いレースでは行わない
- SQL は `pnpm db:query`。値は必ず `--params` で渡す
- 裏取りの基準は予想のときと同じ。**2回試して確からしい値が取れなければ、取れなかったと残す**
- **予想時点の前提（`race_prediction_conditions`）には手を入れない。** 実際の馬場は `races` 側に
  入るので、前提を直す理由が無い。**当日の情報で公開済みの予想を書き換えない**

### ラップを入れる

区間ごとのラップは `race_laps` に、**1区間1行**で入れる。順序は `lap_number`（スタート側から
1で始まる）、単位はミリ秒とメートル。

```sql
INSERT INTO race_laps (race_id, lap_number, distance_m, time_ms) VALUES ($1, $2, $3, $4)
ON CONFLICT (race_id, lap_number) DO UPDATE
  SET distance_m = EXCLUDED.distance_m, time_ms = EXCLUDED.time_ms
RETURNING id;
```

- **区間の本数を決め打ちしない。** 2000m なら200mずつで10区間になるが、距離や取得元によって
  区間の数も長さも変わる。**取れた形のまま入れる**
- **取れなかった区間を0で埋めない。** `time_ms` を空にするか、その行を作らない。0 は CHECK が弾く
- **ラップが取れなくても、そこで止まらない。** 入れられなかったことを 2 の呼び出しで伝えれば、
  役は前半の速さを断定せずに書く（→
  [docs/agent-design.md](../../../docs/agent-design.md#ペースはラップから読む無いなら断定しない)）

### レース後のコメントも入れる

騎手と陣営がレースを終えて述べたことは、`entry_comments` に `race_phase = 'レース後'` で
1件1行入れる。形と守ることは
[register-race](../register-race/SKILL.md#騎手と陣営のコメントは-entry_comments-に入れる情報を集める役)と同じ。

- **レース前のぶんを消したり書き換えたりしない。** 同じ出走に前と後の両方が並ぶのが正しい形で、
  **説明が入れ替わったことは、並んでいて初めて見える**
- **述べられたことを、そのまま結果の理由として `entry_notes` に書かない。** 表明された認識で
  あって事実ではないので、実際の走りと突き合わせる（読み方は
  [docs/agent-design.md](../../../docs/agent-design.md#コメントをどう読むか2026-08-17-決定)）
- 人間がレース後のコメントの含意を渡してくれたなら、それも `interpretation` に残す

## 2. レースを評価する（分析する役）

`race-analyst` を呼ぶ。**1レースにつき1回。** 前半が速かったのか、馬場がどちらに傾いていたか、
相手関係から見てどの程度の内容だったかを読んで `race_notes` に残す。

渡すのは**どのレースかと、人間から出た観察**（見た印象、レース後のコメント）。DB から読める
ものは役が自分で引く。**ラップも `race_laps` から役が自分で引く**ので、渡さなくてよい。

## 3. 出走を1つずつ読み直す（分析する役）

`entry-analyst` を呼ぶ。**1回の呼び出しで1つの出走**なので、16頭なら16回呼ぶ。

- **2 が終わってから呼ぶ。** レースの評価が `race_notes` にあると、その出走を「レース全体の中で
  どうだったか」として読める
- 予想の時点で書いた `entry_notes` があるなら上書きになる。**役が読んでから書く**
- **人間しか持っていないものは、呼ぶときに渡さないと使われない。** 映像を見て気づいた不利や
  折り合い、レースを見た印象、その場にいて分かったこと。**役は映像を見られない**
- **外部情報も調査資料として渡す。** 回顧や記事、動画で確認したことは、情報を集める役が先に
  集めて渡す。**分析する役は自分で見に行かない。** 判断に効く材料が足りないときは、必要な事実を
  「未登録・未分析」へ書いて進行役へ返す
- **コメントも渡さなくてよい。** `entry_comments` に入れてあるので、役が対象と時点を指定して
  自分で引く（`WHERE entry_id = $1 ORDER BY spoken_on, id`）

**書き込むのは、返答の `## 保存する本文` の中身だけ。** `## 保存しないメモ` は書き込まず、
次に何をするかを決めるために読む（→
[docs/agent-design.md](../../../docs/agent-design.md#評価の本文と返すだけのメモ2026-08-18-決定)）。
足りなかった材料・他の役へ渡すもの・人間に聞きたいことはメモの側にあるので、**そこから 4 と 8 で
何を挙げるかを決める。**

**`entry_notes` に残すのは、その出走の中で起きた事実と、そこからの読みまで。**
前後の出走をつないで馬の性質を出さない。**次の出走での扱いも、AI から書かない。** 人間が
そのレースの解釈として明示したときだけ、誰の解釈かが分かる形で残す（→
[docs/agent-design.md](../../../docs/agent-design.md#1つの出走から結論にしてよい範囲2026-09-01-決定)）。

**`horse_notes` はここでは更新しない。** 馬のまとめを触るのは 5 で、そこでも変わった項目だけを
差し替える。この段階では今回の `entry_notes` を残すところまでにする。

**`entry-analyst` は自分で `entry_notes` へ書き込む役なので、書き込む前に自分で実行確認を
通す**（→ [docs/analysis-quality.md](../../../docs/analysis-quality.md#実行時の確認)）。
**受け取った側でも、返答をファイルへ書き出してもう一度確かめる。**

```
pnpm analysis:confirm -- --kind entry --response <返答を保存したファイル>
```

**通らなければ、その出走の評価をそのまま使わない。** 役へ差し戻し、直った返答で書き直させる。
既に書き込まれていたら、そこで先へ進まずに直す。

## 4. 人間の観察と照合する

**ここを飛ばして終わりにしない**（→
[docs/agent-design.md](../../../docs/agent-design.md#4-人間の観察と照合する2026-09-01-決定)）。

1. 人間から渡された映像所見と、レース後のコメントの含意を**項目ごとに並べる**
2. それぞれが `race_notes` `entry_notes` のどこへ反映されたかを1つずつ照合する
3. **入力にあったのに本文で欠けたもの、数値にできないことだけを理由に弱めたものが1つでも
   あれば完了しない。** 直してから先へ進む
4. 観察が通過順・ラップ・コメントと食い違うなら、黙って落とさず、**どこが食い違うかを出して
   対話へ戻す**

同時に、レースと各出走について**その対象の中で起きた事実と、そこからの読みが本文の中心に
なっているか**を見る（→
[docs/agent-design.md](../../../docs/agent-design.md#4-人間の観察と照合する2026-09-01-決定)）。
分からなかったこと、経験していない条件、次の出走での扱いを AI が自発的に足しているなら、
保存しないメモへ移してから完了する。**人間がそのレースの解釈として次の扱いを明示した場合だけ、
その内容を本文に残す。**

**不要な記載を外した結果、短い結論だけになっていないかも見る。** 各出走について、ラップと位置の
関係、動いた区間、同じ展開利を受けた相手との比較、負荷、上がりと着差から読める差の生まれ方のうち、
実際に判断へ使ったものが根拠と解釈まで残っていなければ完了しない。出走評価が700文字程度を
下回るときは材料を読み直す。700文字は完成条件でも上限でもなく、特筆事項があれば必要な分だけ
増やす。文字数を作るための推測や重複は足さない。

## 5. 馬のまとめの差分を作る（分析する役）

`horse-analyst` を呼ぶ。**1回の呼び出しで1頭**なので、16頭なら16回呼ぶ。**同じ馬のまとめを
2つの呼び出しから同時に触らない。**

- **4 が終わってから呼ぶ。** 出走の評価が確定し、人間の観察と照合し終える前に呼ぶと、あとで
  変わる材料でまとめを動かすことになる
- **今回の出走評価をまとめへ足すために呼ぶのではない。** その馬についての現在の結論が今回の
  出走で変わった項目だけを差し替える（→
  [docs/analysis-quality.md](../../../docs/analysis-quality.md#レース振り返り後の更新)）
- 渡すのは**どの馬のどの出走かと、人間から出た観察、渡された調査資料**。DB から読めるものは役が
  自分で引く
- 返ってくるのは、`## 保存する本文` に**変える項目の見出しと、置き換わったあとの本文**、
  `## 保存しないメモ` に**変えた理由・根拠になった出走・実行確認**
- **変わる項目が無ければ、役は `## 保存する本文` に「変更なし」とだけ書く。** それも正しい結果
  なので、1項目でも変えさせようとしない。まだまとめが無い馬だけは、初回のまとめを作らせる
- **ここでは DB へ書かない。** 反映するのは 7 の検証を通ってから

**返答を受け取ったら、保存する前に実行確認を見る。**

```
pnpm analysis:confirm -- --kind horse --response <返答を保存したファイル>
```

**実行確認が無い、一般ルールか参考例のどちらかが無い、種類と参考例が対応していない、保存する
本文に混ざっているときは、その返答を使わない。** 役へ差し戻す。

**次の2つに当たる馬は、自動で更新しない。**

| 起きていること | どうするか |
| --- | --- |
| `author` が「人間」「対話」 | 変更前・変更後・変わる理由を項目ごとに並べて対話へ戻す。合意が取れるまでその行を触らない |
| 既存本文を12項目の見出しに読み分けられない | 一部を差し替えず、全文の書き直し候補と読み分けられない箇所を対話へ戻す |

**`horse_notes` がまだ無い馬は、今回の出走だけを材料にしない。** 現在までの全材料から、根拠の
ある項目を初回のまとめとして作る。

## 6. 予想と買い目の答え合わせ（分析する役）

**当たったかどうかではなく、どこで筋道が外れたかを見る。** 印は結論なので、当否を数えても
次に効かない。

- 予想の展開（`race_predictions.body`）と実際の隊列を突き合わせる。**各時点の隊列まで出して
  あるので、どの地点から違ったかが分かる**
- `ai_bets` の `payout` `refund` は、1 の事実登録で入っている値を読む。**分析する役はここで
  書き換えない。** 空なら答え合わせを始めず、「未登録・未分析」へ書いて進行役へ返す
- 出すのは購入額・払戻額・回収率に加えて、**買い方単位の的中率（的中した買い方 ÷ 買い方の数）と、
  展開後の点数単位の的中率（的中した点数 ÷ 総点数）の2つ**。**どちらの分母かを書かずに
  「的中率」とだけ出さない**
- **`race_payouts` に入れた確定払戻と突き合わせて検算済みかを確認する。** ただし回収率の計算には
  使わない
- **買っていない馬券が当たっていたことを、外れの理由にしない**

## 7. 検証して馬の差分を反映する

**評価を更新し終えたら `verifier` を呼ぶ。** 分析の結果を蓄積と突き合わせて、根拠が通って
いるかを突いてもらう。**このとき、人間から渡された観察も一緒に渡す。** 渡さないと、本文から
欠落していないかを確かめられない。**指摘を受けて直すのはオーケストレーターか、差し戻された分析する役**で、
検証した側は直さない（[docs/agent-design.md](../../../docs/agent-design.md#検証の手順2026-08-16-決定)）。

**`verifier` の返答も、同じ形で実行確認を確かめる。** 検証した種類のぶんだけ返ってくるので、
出走の分析は必ず、馬のまとめを検証したならそれも指定する。

```
pnpm analysis:confirm -- --kind entry --kind horse --response <検証の返答を保存したファイル>
```

**通らなければ、その検証の結果を受け取らない。** 検証する側が一般ルールと参考例を読んでいない
まま突いたことになるので、`verifier` を呼び直す。

**馬のまとめは、検証を通ってから反映する。** 変更前の本文と更新候補を項目ごとに比べ、変えると
宣言した項目以外が一字も変わっていないこと、今回の `entry_notes` の全文や当日だけの状態が
移っていないことを確かめてもらう。指摘があれば `horse-analyst` へ差し戻す。

**問題が無ければ、項目単位で結合してから書き込む。本文を手で組み直さない。**

```
pnpm db:query "SELECT body, author FROM horse_notes WHERE horse_id = $1" --params '[123]'
pnpm horse:summary -- --current <既存本文のファイル> --response <返答のファイル> --author <author>
```

- 引いた `body` をファイルへ保存してから `--current` に渡す。まだ無い馬は `--current` を省くと、
  返答の項目を初回のまとめとして組む
- 出てきた本文を `pnpm db:query --file` で `horse_notes` へ書き込む
- **変わる項目が無かった馬は、「変わる項目が無い」と出て本文が出ない。** それが正しい結果なので、
  書き込まずに次の馬へ進む。`updated_at` も動かさない
- **実行確認の無い返答からは本文が出ない。** 入口が理由を出して止まるので、役へ差し戻す
- 書き換えられない理由（`author` が人間・対話、既存本文を読み分けられない）が出たときは、
  その馬を対話へ戻し、ほかの馬の反映は続ける

## 8. 気づいたことを挙げる

**残す先が2つある。何についての気づきかで決まる。**

| 気づいたこと | 残す先 |
| --- | --- |
| コース・騎手・厩舎の見方が変わった | 各 `*_notes` |
| 見るべきものを見落としていた、順序が違った | `docs/` と `agent/skills/` |

**その馬についての評価は、3 の `entry_notes` と 5 から 7 の `horse_notes` で残してある。**
ここで馬のまとめを作り直さない。**人間が明示していない次の出走での扱いも、ここから作らない。**

後者を直すのは `improve-agent` の担当。**ここでは挙げるところまでを行い、直すかどうかは対話で

## 人間に聞くこと

**承認は求めない。** 聞くのは人間にしか無いものだけ — 走りを見た印象、レース後のコメントの
含意、陣営の事情。**問いを出しても止まらず、分かる範囲を書いて先へ進む**
（[docs/product.md](../../../docs/product.md#人間に何を聞くか)）。

## 止まるところ

- **`author` が「人間」「対話」の評価は、単独で書き換えない。** 前の見方・新しい見方・何がどう
  変わるのか・なぜ変わるのかを並べて合意を取る。合意が取れるまでその行は触らない
- **結果が出たことを理由に、予想そのものをさかのぼって直さない。** 予想は枠順確定直後に出した
  もので、回収率もそれで測ると決めてある
