# 調査資料を使う

情報を集める役、分析する役、文章を確認する役は固定しない。1つのエージェントがすべてを担っても、
複数のエージェントで分けてもよい。分析する役は、渡された調査資料と、登録済みの事実を材料に
分析・予想を行う。

**Phase 1 の Codex から Claude Code へ渡す経路では、Codex が収集・事実のDB登録・文章確認、
Claude Code が分析と分析結果の保存を担う。** これは現在の運用であって固定しない。資料の受け渡し方や
担当は、精度と使いやすさを見て都度変える。本人が Codex 単体、Claude Code 単体を指定したときは、
同じ実行元が収集から確認までを順番に行う。

## 受け取る資料

調査資料は、タスクMarkdownの「事前調査」と「参照元」に置かれている。進行役がDBへ登録して
読み直した結果は「事実の登録結果」にある。進行役が準備を終えた（`preparation_status: ready`）
タスクから、まずこの3つを読む。

調査資料には、少なくとも次の情報があるかを確かめる。

- 何を確かめるために集めたか
- 出典と確認時点
- 確認できた事実
- 動画なら該当時点、話者、発言か映像で確認したことか
- 情報源どうしで食い違う点
- 取れなかった情報

ページや動画の本文をそのまま DB へ残さない。発言、映像で確認したこと、そこからの読みを混ぜない。

## 進め方

1. まず DB と調査資料を読み、分析に使える事実が登録済みかを確かめる。
2. 対象に合う分析する役を呼ぶ。
3. 評価と予想を作ったら、検証する役で根拠のつながりを確かめる。
4. 材料不足や食い違いが判断に効くなら、必要な情報を資料の作成者へ返す。

**自分で外部サイトや動画を見に行かない。事実データを DB へ登録しない。** 馬・レース・出走・
血統関係・結果・ラップ・払戻・コメント・メモは、外部情報や人間の入力から確かめられて評価では
変わらないもので、集めるのも登録するのも資料の作成者の担当である。DB へ保存してよいのは、
根拠から導いた分析結果（`*_notes`、印、予想、AI の買い目）だけ。**競馬の分析として起動された
Claude Code は、事実のテーブルを更新しようとしても `pnpm db:query` が拒否する。**

資料の作成者へ返すときは、「情報が足りない」とだけ書かない。対象、確かめたい内容、その情報が
どの判断に必要かを1件ずつ示し、タスクMarkdownの「未登録・未分析」へ残す。資料の作成者が
調べて登録し終えたら、同じ実行を再開して続きから進める。

## 最後の文章確認

登録する本文や人間へ返す文は、文章確認を担う役の確認を通す。確認するのは、造語、不自然な
比喩、根拠より強い断定、事実と読み取りの混同、競馬の話として読めない表現である。

指摘があれば、原則として分析を担った役が直す。分析を担った実行元が利用上限や外部エラーで
続けられず、保存済みまたは作成途中の分析をそのまま使って表現の修正や確認だけで完了できる場合は、
文章確認を担う側が残りを引き継いでよい。分析の中心部分を作り直す必要があるなら、本人の指示なしに
実行元を切り替えない。引き継いだ場合は、既にできていたことと自分が行ったことをタスクへ分けて残す。
