# コンセプト

## 名前

vates（ラテン語で予言者・詩人）+ steed（駿馬）。「優駿を予言する者」と「思考プロセスを
言語化する」の二層構造。

## 位置付け

- 本線: 自分が競馬を楽しむための補助ツール + 個人開発を楽しむための題材
- サブ: 認知獲得 → 将来的に note 等での有料販売
- **完全自動化は目指さない。** 人間がオトモとして使う前提

## コアコンセプト

「回収率を売る」のではなく **「予想の裏側にある AI の思考回路を売る」**。

中核目的は、**AI と人間の思考のいいとこ取りをすること**。

数値テーブルに落とし込んだ瞬間に失われる情報がある。着順・タイム・人気は「結果」であって
「その馬の能力や状態」そのものではない。人間の競馬ファンは数字の背後にある文脈・経緯・
事情を読み取って評価を補正している。この補正のプロセスを構造化して扱えるようにする。

**ただし、特定の人間の判断を正解として写し取るわけではない。** 扱いたいのは「数字の背後を読む」
という思考の種類であって、誰かの結論そのものではない。本人が出した実例は「どんな情報が必要かを
示す材料」として扱い、仕様として固定しない。

### AI と人間の分担

| 人間が強い | AI が強い |
| --- | --- |
| 映像を見て「強引にハナを取り返した」と気づく | 全レース・全頭を漏れなく処理する |
| コメントの含意、陣営の事情、遠征の経緯 | 忘れない。ブレない。気分で評価が動かない |
| 「誰が見てもわかる」文脈の重み付け | 大量の過去走の突き合わせ、集計 |
| 見るべき馬を絞る | 過去の自分の評価との矛盾を検出する |

**人間が「あまり意識していない」と答えた領域は、思考の対象外ではなく AI に寄せる候補**として
扱う。たとえば成長曲線は人間が毎回わざわざ考えるものではないが、全頭ぶんを年齢とレース結果から
機械的に並べるのは AI の得意分野になる。

## 再現したい思考の範囲

**以下は例示であり、これが全てではない。**

- レース内容の質の評価（着順は悪いが内容は濃い、恵まれた勝利、など）
- 相手関係・レースレベルの推定
- 展開・隊列・不利の影響の読み取り
- ローテーション、調整過程、遠征や輸送、休養明けの解釈
- 馬場状態・コース適性・距離適性の見立て
- 陣営や騎手のコメントに込められた含意の読み取り
- 成長曲線・年齢・馬体の変化の評価
- 度外視すべき一戦かどうかの判断
- 血統から見た将来的な適性の推定

**重要**: これらは「特定のパターンを個別に例外処理する」話ではない。人間が競馬新聞や
データを目で並べて頭で考えているプロセスそのものの再現を目指している。個別パターンの
列挙で網羅しようとする設計は、この目的から外れる。

## 差別化

- 既存の競馬AIは LightGBM 等の数値モデルが主流
- 本プロジェクトは LLM エージェントで非構造テキスト（回顧記事・陣営コメント・遠征経緯）を
  解釈する
- 騎手・陣営のレース後コメントを長期蓄積して評価に使う機能は、調査した範囲では他に
  見当たらない

## 継続的改善サイクル

一度作って終わりではなく、**日々改善を加え続けること自体をプロジェクトの本質に据える**。
毎週レース結果というフィードバックが得られるドメインなので相性が良い。

予想がズレた際に「どの判断が誤ったか」を思考ログから特定し、該当する skill やプロンプトを
修正していく。このプロセス自体が継続的な技術記事のネタになる。
