## 確定していること

### DB の分け方

- DBインスタンスは1つ。テーブルで分ける
- **AI の予想・購入** と **自分の予想・購入** は別テーブル
- 自分の購入はエージェントの学習に自動反映しない（明示的にスキルを叩いたときだけ反映）

背景は [architecture.md](architecture.md#データベース) を参照。

### `viewer_grants`

アクセス制御用。Phase 1 では作るだけで参照しない。

| カラム | 内容 |
| --- | --- |
| `email` | ログインの識別子 |
| `access_level` | `owner` / `friend` / `member` / `public` |
| `grant_source` | `owner` / `manual` / `note` |

`grant_source` は画面判定に使わない。将来 note のメンバー一覧CSVを同期する際、
`grant_source = 'note'` の行だけを洗い替えるために必要（`manual` の友達を巻き込んで消す
事故を防ぐ）。

### 予想レコードの公開タイミング

予想レコードに `published_at` と `public_at` の2つを持たせると、「member は直後、一般は
結果確定後」が時間で表現できる。

※ 有料化への備えとしての案であり、カラム名・型は未確定。

## 分析対象の広がり

分析対象はレースだけではない。少なくとも以下が対象になる。**例示であり、これが全てではない。**

- レース / 出走
- 馬（プロファイル、成長曲線、馬体の変化）
- 騎手
- 厩舎・調教師・陣営
- 血統（父・母・きょうだい・一族）
- 馬場・コース
- 陣営や騎手のコメント

これらがそれぞれ蓄積対象になるため、データ量はレース数だけからは見積もれない。ストレージの
概算は [architecture.md](architecture.md#ストレージ見積もり) を参照。
