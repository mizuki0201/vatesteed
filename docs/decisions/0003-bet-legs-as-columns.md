# 買い目は「列」で保存し、展開した組み合わせは持たない

- 日付: 2026-08-08
- 状態: 採用

## 背景

馬券には買い方が複数ある。単点・ボックス・流し・フォーメーション、さらに馬単と3連単には
マルチがある。3連複の流しなら1枚の投票が6点に、フォーメーションなら7点にというように、
**1回の購入が複数の買い目に展開される。**

回収率を出すには点数と的中の判定が要る。何を保存すれば両方が出せるかを決める必要があった。

## 決定

**`bet_legs` には「何列目にどの馬か」だけを保存し、展開した買い目は保存しない。**

- **すべての買い方を列で表す。** `bet_style`（単点 / ボックス / 流し / フォーメーション）は
  人間が読むためのラベルで、計算には使わない
- **列の数は券種が必要とする頭数と同じ。** 単勝1列、馬連2列、3連複3列
- 流しは「軸の列 + 相手を残りの列すべてに」、ボックスは「全列に同じ集合」として埋める
- 点数と的中は、保存された列から毎回計算して出す

3連複の軸1頭流し（軸=1、相手=2,3,4,5）なら、列1={1}、列2と列3の両方に {2,3,4,5} を入れる。
これで展開すると6点になる。

## 検討したが採らなかった案

**展開した買い目を1点ずつ保存する案。**

的中の照合が単純な一致で済むが、次の理由で採らなかった。

- 行数が増える。3連単のボックスは1回の購入で数十点から数百点になる
- **買い方の情報が失われる。** 記事に「タバル軸の3連複流し」と書きたいのに、展開後は
  ただの組み合わせの列挙になる
- 列さえあれば展開は何度でも再現できるので、保存する必要が無い。保存すると、
  あとで点数の計算を直したときに保存済みの行とズレる

なお、途中まで「流しは軸の列と相手の列の2列」という表現を検討していたが、これは誤り。
3連複なら3列必要で、相手の集合を2列に複製する形でないと展開できない。

## 影響

- `combination_count` と `total_amount` は導出値になる。**`expandBet` の計算結果だけを入れ、
  手では入れない**
- 枠連は馬ではなく枠で買うため、`bet_legs` に `bracket_number` を持たせ、`entry_id` と
  排他にする必要が出た（CHECK制約）
- 枠連のゾロ目（同枠2頭で1着2着）があるため、「同じ値が2回出たら捨てる」処理は枠連には
  適用しない（ボックスを除く）
- WIN5 も同じ形で入る。`leg_group` を「対象5レースの発走順で1〜5」として使う。
  5レースまたぎなので `bets.race_id` は null になる
