# マイグレーション運用と ORM

- 日付: 2026-08-09
- 状態: 採用

## 背景

スキーマの叩き台は [data-model.md](../data-model.md) で 22テーブルぶん決まったが、実際に
`CREATE TABLE` を流す手段が決まっていなかった。ORM を採るとスキーマ定義が TypeScript に
なるため、書き方そのものが変わる。先に決める必要があった。

効いてくる制約が2つあった。

- **本番DBのコピーで試す手段が無い。** Neon の Preview ブランチ作成を無効にしているため
  （[architecture.md](../architecture.md#ブランチ運用)）
- Phase 1 では eve ランタイムを起動せず、Claude Code が `lib/` を直接呼ぶ

## 決定

### ORM は使わない

スキーマの正本は `data-model.md` のまま。TypeScript に写さない。

- **Phase 1 で DB を一番叩くのは SQL を書く Claude Code** なので、ORM の主な取り分である
  「手書きコードの型」がほとんど効かない
- `expandBet` / `isHit` は取得後のただの計算で、ORM を必要としない
- **一方通行にならない。** Drizzle には既存DBから TypeScript のスキーマ定義を起こす機能が
  あるので、後から入れられる

見直すタイミングは、ダッシュボードに本気のクエリが増えたとき、または Phase 3。

### マイグレーションは手書きSQL + 自前の適用スクリプト

```
db/migrations/0001_initial.sql
lib/db/migrate.ts     ← 適用ロジック
```

- 適用済みファイル名を `schema_migrations` に記録し、未適用を番号順に流す
- **1ファイル = 1トランザクション。** 途中で落ちたらそのファイルは丸ごと戻る
- 適用スクリプトだけ `pg`（node-postgres）で `DATABASE_URL_UNPOOLED` に直結する。実行時に
  使う `@neondatabase/serverless` は HTTP 経由で、複数の文をまたぐトランザクションを張れない
- **流すのは人間が手で `pnpm db:migrate`。** Vercel のビルドからは流さない。デプロイの
  たびに本番DBへ走ってしまうため
- 流したファイルは後から書き換えない。変更は次の番号で足す

### 試す場所は Neon の手動ブランチ1本

`vatesteed` プロジェクトに `migration-test` を1本作り、**必ずそこで通してから本番に流す**。
Vercel 連携の自動ブランチ作成は無効のまま。

使う前に「親からリセット」して本番と同じ状態にしてから試す。ブランチはコピーオンライトなので
作成は一瞬で、容量は差分しか乗らない。

### ロールバックは書かない。事前のブランチで守る

- **down は書かない。** 間違えたら次の番号で直す
- **Neon の復元（point-in-time restore）は保険にしない。** 無料プランは6時間・延長不可・
  ルートブランチのみ。週末に流して翌日気づく、という時間の流れに対して短すぎる
- 代わりに、**データを失う変更（DROP / 型変更 / NOT NULL 化など）を流す前に Neon のブランチを
  1本切る。** ブランチは6時間で消えないので、この用途では復元より素直に強い。要らなくなったら
  消す（無料プランのブランチ上限は10）
- テーブル追加・カラム追加のような安全な変更ではブランチを切らない

## 検討したが採らなかった案

**Drizzle を今入れる。** スキーマ定義を TypeScript に置き、`drizzle-kit` に差分の SQL を
生成させる案。22テーブルの変更が続く時期には労力を減らせるが、**`data-model.md` と TypeScript
という正本が2つになる状態が即日始まる**。今すでに日本語で全部書けているものを写す作業に
見合わない。後から入れられるので急がない。

**Prisma。** マイグレーション生成時に検証用の別DB（shadow database）を要求する作りで、
「試す場所が無い」という今の制約と正面からぶつかる。

**down マイグレーションを書く。** down はそもそも失われたデータを戻さない。本当に効くのは
「流した直後に構造だけ戻す」場面で、それは6時間の復元窓でも足りる。

## 影響

- `data-model.md` の未確定事項から「マイグレーション運用」が外れた
- `package.json` に `pg` / `@types/pg` と `db:migrate` が入った
- **`migration-test` ブランチを Neon の画面で作る作業が残っている**（このリポジトリからは
  作れない）
