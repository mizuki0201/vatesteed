# evals

eve の eval（採点付きの回帰テスト）を置く場所。**中身はまだ空で、動かすのは Phase 3。**

eval は実際にエージェントを起動して1〜複数ターン会話させ、結果を採点する仕組みなので、
eve ランタイムが要る。Phase 1 のいまは eve ランタイムを動かさないため、ここでは
**枠と「何を検証したいか」だけ**を置いておく。

`lib/` の純粋なロジック（買い目の展開、的中判定、回収率、レース名の正規化）は `node:test` の
単体テストで見る。**eval で見たいのは、そこではなくエージェントの振る舞い**のほう。

## 動かすときに必要になるもの

| もの | 内容 |
| --- | --- |
| `evals/evals.config.ts` | 必須。judge に使うモデルと共通設定を書く |
| `evals/**/*.eval.ts` | 1ファイル1 eval。ファイルパスがそのまま eval の id になる |
| `eve eval` | 実行コマンド。CI では `eve eval --strict` |

判定は3種類ある。ツールを呼んだか・成功したかのような**決め打ちできるものは gate**（落ちたら失敗）、
文章の質のように**揺れるものは judge で soft**（記録は残るが落とさない）に寄せる。

## 検証したいこと（頭出し）

**これは案出しであって、確定した eval のリストではない。** 実際に書くのは Phase 3。

### 振る舞いの下限（gate 寄り）

- **勝手に埋めない。** 取得できない情報や判断に迷う情報があるとき、推測で埋めずに人間へ確認を
  返すか。README とコンセプトの根幹なので、これが崩れたら気づきたい
- **未確定を確定させない。** `docs/` で「未確定」とされている論点を聞いたとき、断定せずに
  確認を求めるか
- **自動アクセス禁止ドメインを踏まない。** [compliance.md](../docs/compliance.md) のリストに
  あるドメインへ取得ツールを向けないか。**リストが空のいまは自動収集そのものを行わない**ので、
  その状態も含めて確認する
- **計算を暗算しない。** 点数・金額・回収率・的中判定を自分で書かずに `lib/` 由来のツールを
  呼ぶか。ここは数字が合っていることより「ツールを通ったか」を見る
- **skill が起動する。** タスクの依頼で `task-management` が読まれるか。スキルを増やすほど、
  意図した場面で意図したスキルが選ばれるかが効いてくる

### 出力の質（judge 寄り）

- **理由が付いている。** 予想の出力に、結論だけでなく「なぜそう判断したか」が含まれるか
- **結果と能力を混同していない。** 着順・タイム・人気をそのまま能力の根拠として扱っていないか
- **蓄積したナレッジを使っている。** 馬プロファイルや過去の評価がある馬について、それを踏まえた
  内容になっているか（外から取り直しただけになっていないか）

### 回帰として効かせたい場面

- `agent/instructions.md` を書き換えたとき
- スキルを追加・改訂したとき
- サブエージェントに分割したとき（分割前後で振る舞いが変わっていないか）
